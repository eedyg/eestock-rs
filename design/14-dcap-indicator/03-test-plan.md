> 对应 ADR-021、`02-spec.md`。**TDD 纪律：先写失败测试，再最小实现，重构在测试保护下。**

## 0. 浮点确定性铁律（本计划的地基，先读这条）

ADR-021 要求「两个产物算同一个数」。要让这件事**可机械断言**，CORE 必须满足两条硬约束（违者 D4/D5 断言必然红）：

| 约束 | 原因 |
|---|---|
| **禁止 `Math.pow` / `Math.exp` / `Math.log`** —— `r^(k−1)` 用**迭代乘法**（`w *= r`） | IEEE754 只对 `+ − × ÷ √` 逐位可复现；`pow/exp/log` 的实现留给引擎，V8 与 QuickJS 可能差 1 ulp |
| **禁止增量累加优化**（不得维护 running sum 推进）—— 每 bar 必须在窗口上完整重算，且**累加顺序按 `02-spec.md` §4 第 3 条的两步法钉死**：① 先 `k = 1..n` 升序迭代乘法求权重 `A_k`；② 再 `k = n → 1` 往回累加 `ΣA_k` 与 `Σ(A_k/P_k)` | 累加顺序不同则浮点尾数不同（实测 `r=1.2` 下两步法 `…7547845` vs 前进累加 `…7545625`，差 `2.2e-16`）⇒ 结果不逐位相等。`n ≤ 250`、`m ≤ 60`，重算成本可接受 |
| **CORE 区间 = 无类型注解的 ES2015 子集** | 同一段字节既要进 `.ts`（Vite/TS 转译）又要被 **rquickjs 直接求值**（不剥类型注解）⇒ CORE 内不得有 TS 注解/`import`/`export` |

由此得到**两个严格的等价层级**，测试必须分清：

- **逐位相等**（`===` / 字节）适用于：镜像体（T3）、跨运行时（T4）、`smooth=0 ≡ raw`（T2）、`save/load` 重放（T7）。
- **容差相等**仅适用于 T1（`r=1 ≡ 遗留 DCAP`）—— 因为两种代数排列（`Σ A_k/P_k` vs `1/HM`）**求和顺序天生不同**，实测差异量级 `~2.2e-16`（示例见 T1）。

## 1. 测试清单

### T1 口径基准：`r=1 ≡ 遗留 DCAP`（容差）
- 输入 `closes = [100, 90, 95]`，`n=3`，`r=1`：
  - 本指标 ROI = `0.0018518518518517713`
  - 遗留 DCAP（`close/HM−1`）= `0.0018518518518519933`
  - ⇒ 断言 `|Δ| ≤ 1e-12`（**禁止**写成逐位相等）
- 输入 `closes = [100, 90, 95]`，`n=3`，`r=1.2` ⇒ `0.0045787545787547845`（**此值依赖 §0 钉死的累加顺序** newest→oldest；故断言用 `|Δ| ≤ 1e-12`，**不要**用 `1e-15` —— 实现若按 oldest→newest 累加会得 `0.0045787545787545625`，1e-15 余量不够稳）
- 补充一组真实数据抽样的回归冻结值（由 tester 用 15m 真实 closes 生成，写死在测试里作**口径冻结**）。

### T2 开关关闭 == 原始值（逐位）
- 对同一输入：`smooth=0` 的输出 === 未平滑原始 ROI（`===` 逐位，含 `null` 位置一致）。
- 反向哨兵：把 CORE 里 `smooth` 分支改成"近似直通"（如加 `×1.0000000001`）⇒ 本测试必须红（防近似路径）。

### T3 镜像体断言（逐字节）
- 读 `web/src/features/indicators/dcap.ts` 与 `crates/strategy-core/reference-plugins/dcap.js`；
- 取 `// === DCAP CORE BEGIN ===` 与 `// === DCAP CORE END ===` 之间的内容，断言**逐字节相同**；
- 负例：删掉任一文件里的哨兵注释 ⇒ 测试红（fail-closed，不得静默跳过）。

### T4 跨运行时逐位等价（黄金样本）
- 同一组样例（≥ 20 组，含边界）分别经：
  - 前端模块（node/vitest，直接 import 生成的 `.ts`）
  - 插件（rquickjs 按 `strategy-runtime` 同款方式求值；可直接用 `strategy-runtime` 的测试夹具）
- **比较对象必须写明确**：插件侧比 **`on_bar(ctx)` 返回的 0–100 分**，前端侧比 **`dcapScore(values, th)`**（标量）；三线**原始值**则比 `dcapRoi`/`computeDcapSeries`（由同一组 closes 驱动，而非从插件外层拿）。
- 断言每条线、每根 bar **逐位相等**（`===`，`null` 位置一致）。
- **必须包含** `r ≠ 1` 的样例（≥ 5 组），否则 pow 类差异测不出来。

### T5 参数约束（**两个面语义不同，均必测**）

**T5a — 插件面 = 确定性归一化（不拒绝、不报错）**（架构裁决，见 `02-spec.md` §2）
| 用例 | 期望 |
|---|---|
| `n_s >= n_m`（如 26/26、60/26） | `init` 后生效值 `n_m' = n_s+1`；三线仍单调 |
| `n_m >= n_l`（如 8/60/26） | `n_l' = n_m'+1` |
| `n_s == n_l`（如 20/20/20） | 归一后满足 `n_s < n_m' < n_l'` |
| **幂等** | 用归一后的参数再次 `init` → 值不再变化 |
| **确定** | 同输入序列 + 同参数 → 逐位同输出（含非法参数情形） |
| `smooth=0` 且 `m` 越界 | 插件不负责拒绝；表现必须确定（`m` 被忽略 ⇒ 等同原始线） |
| 单参数越界（`n`=1/251、`r`=0.49/2.01/NaN/Inf、`m`=0/61、`smooth`=2/−1、`th`=0.0009/0.51） | **不由插件断言**（单参数 `min/max` 是消费方职责，ABI §1 NIT-6）—— 由平台 `fill_and_validate_params` 与 T5b 覆盖 |

**T5b — 配置端点 = 400 拒绝**（宿主自有端点；随 P3 配置端点落地）
| 用例 | 期望 |
|---|---|
| `n_s>=n_m` / `n_m>=n_l` / `n_s==n_l` | `PUT /api/config/dcap` → **400** |
| 越界/非整数（n=1/251、m=0/61、r=0.49/2.01、smooth=2、th 越界） | 400 |
| `GET` 无键 / 坏 JSON / 库中越界旧值 | 回默认（**不 500**） |

### T6 数据不足边界（逐根对齐）
| 可用 bar 数 | `smooth=1` | `smooth=0` |
|---|---|---|
| `n−1` | `null` | `null` |
| `n` | `null`（SMA 未满 m） | 有值 |
| `n+m−2` | `null` | 有值 |
| `n+m−1` | **首个有值**（断言首值位置精确） | 有值 |

- 三条线各自的首次有值位置必须分别按 `n_i + m − 1` 计算（不得用 `n_l` 一刀切）。
- 插件侧：某线不足 → **该线不入 N**；**三线全不足** → 返回 **50**，且 `ctx.log` 无输出（可用日志断言）。

### T7 状态持久化（重放分叉防线，ABI G3）
- 同一段 bar 序列跑两次：一次连续跑；一次在中途 `save()` → 重建实例 → `load()` → 续跑。
- 断言两次结果**逐位相同**（含三线值序列与最终 run 结果）。
- 若 `save/load` 漏掉任一窗口/尾窗元素 ⇒ 必须红。
- **位级保真（实测发现，2026-09-13，必须作为硬要求）**：`serde_json` 的浮点解析**不是正确舍入**（实测 `from_str::<f64>("57.329040578513684")` 差 1 ulp）⇒ 状态若经 JSON 十进制往返，可能破坏逐位一致。故恢复后必须断言**位级**相等；若序列化确实丢 1 ulp，必须改为位串/整型编码，或**上报为架构级问题**——**不得**把断言放成容差来"搞定"。

### T8 前端渲染 spike（实测，非单测）
- `registerIndicator` 注册最小 DCAP 副图指标，验证：
  1. **精度事实核对**：自定义指标**默认 `precision = 4`**（`index.esm.js:3156`）⇒ ①不设 precision：`0.0048` 能显示，但 `0.004578…` 丢第 5 位（→ `0.0046`）；②设 `precision: 5`：`0.0048` 渲染为 **`0.00480`**、`0.004578…` → `0.00458`。断言"5 位尾数可见"，并留双向对比截图（4 位 vs 5 位）；
  2. 数据不足处**断线**，无异常抛出、不打断渲染；
  3. 三 figure（s/m/l）+ 副图独立 Y 轴自动标度；
  4. **`decimalFold` 行为**：构造 `0.00048` 观察折叠形态（`0.0{3}48`），确认是否需要调阈值；
  5. **性能**：`viewport_bars = 600`、`n_l = 250`、`m = 60` 时 `computeDcapSeries` 的耗时（目标：单次 < 16 ms，否则需降采样或缓存）。
- 产出：断言 + 截图（截图入 PR，作为"显示对"的证据）。

### T9 tangle 门禁（两个方向都要红）
- 改文档块、不重跑 `tangle` ⇒ `./scripts/check-tangle.sh` **红**（漂移）；
- 直接手改生成物、不回写文档 ⇒ 同样**红**；
- **首次产出 js 文件时**回归 ADR-018 的"假绿"用例（冲突仍 exit=0 的旧失败模式），确认 js 产物类型不引入假绿（JS 是 entangled 内置语言，无需改 `entangled.toml`）。

### T10 图表取数 warmup
- 请求 `limit = viewport_bars + (n_l + m − 1)` 后，**视口最左侧那根 bar 已有 dcap 值**（不断线）；
- 反例（不 warmup）首根为 `null`（记录为已知表现）。

### T11 配置 API
- `GET` 无键 → 默认 8 参数；库中旧值/坏 JSON → 回默认（不 500）；
- `PUT` 合法 → 200 且回读一致；非法（`n_s<n_m<n_l` 不成立 / 越界）→ 400；
- 前端：mount 读取失败重试 + focus 重读（ADR-020 韧性要求）——用测试桩验证重读触发。

### T12 播种与清单
- `reference_plugins()` 长度 **7 → 8**、`BUILTIN_ORDER` 追加 `dcap`、播种计数测试 **11 → 12**、幂等性保持；
- `id` 唯一性、`code` 非空（现有断言继续覆盖）。

## 3. 有效性验证（**独立任务，不阻塞上线**）

指标功能正确 ≠ 指标有预测价值。按既有 SWEEP 纪律独立排期：IS 前 70% 冻结参数（中位数）→ OOS 一次性裁决 → 双跑 sha256 一致。

**先验（必须带入，避免重复劳动）**：
- `r=1` 即遗留 DCAP，已有结论：`dcap12` 五年领先、`dcap8<−1%` 是最强子信号、**15m 阶梯定投捕获 0.088 < 日线 0.207**；
- ⇒ 待验证的**新增信息量只在 `0 < r ≠ 1`（建议先扫 1.00–1.05）与三线 r 的差异化配置**上；`r ≫ 1` 已退化到 ROC_1（与 `momentum.js` 范式重叠）、`r → 0` 退化为 n 根 ROC。
- 参数空间建议：`r` 稀疏点（1.00/1.02/1.05/1.2）、`m ∈ {1,3,5,10}`、`smooth` 固定 1（`smooth` 不必扫，`m=1` 已等价关闭）。
