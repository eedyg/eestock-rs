# ADR-014：自定义 Metrics 扩展框架

- 状态：✅ 已定（2026-09-02 用户拍板）
- 背景：旧系统有自研指标计算（metrics 表 + 周期边界计算），新系统须支持自定义指标扩展（用户明确要求）
- 决策：
  1. **代码迭代制**（4a-A）：`MetricCalculator` trait + 编译期注册；自定义指标 = 一次文学式+TDD 迭代（与回测策略同哲学）。表达式引擎为未来可选增强，另议
  2. **计算时机**：新 bar 写入时增量计算（周期边界触发）+ 历史回填重算工具（4b 推荐案）
  3. **存储**：`metrics` hypertable `(code, period, ts, metric, value)`，同库同压缩策略
  4. **消费**：看板叠加 / 回测引擎引用 / API / MCP
- 内置首批（4c 全要）：MA / EMA / MACD / KDJ / BOLL / RSI / ATR / 换手率 / **筹码分布**
- ⚠️ 双轨澄清：Wave 1 看板的 MA/MACD/KDJ/BOLL 由 klinecharts **前端内置**渲染（零后端成本）；服务端 metrics 框架 Wave 2 落地，服务回测/自定义指标/API/MCP。两轨并存不矛盾，但**同名指标口径必须一致**（契约测试锁定，前端口径以服务端为准）
- 筹码分布特化：标量衍生值（获利比例/平均成本/90·70 成本区间/集中度）入 metrics 表（日级）；完整分布（价位→筹码占比）入专用 `chip_distribution` 表（ADR-011 自算路线）
