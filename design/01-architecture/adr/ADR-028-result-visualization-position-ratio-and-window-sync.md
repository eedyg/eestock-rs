# ADR-028 回测结果可视化：持仓比率序列、结果页时间窗联动、L1/L2 跳转定位

- 状态：**已裁决（2026-09-20，Grill 补充四问 + 「全部按推荐」+ 按钮语义 ②）**，待实现
- **批次**：与 **ADR-027 同批实现**（合并为「结果载荷 v2」不兼容批次，M1）。理由：两者都改 result payload / curve kinds / migrations，而 ADR-027 D3 已授权清空历史 ⇒ 只有**一次**清空与一次不兼容发版机会。
- 取代/影响：**修订** `/curve` 契约（增时间窗参数，向后兼容）；**修订** `BarRecord`（增持仓快照）；新增可抽样曲线 kind；**不改** `/result`、`/bars`、`/fills` 的既有形状；**不破** ADR-020（回到最新语义）与 ADR-022（跨图同步原语）
- 触发需求（用户原话）：①「还需要一个视图来展示持仓比率，就像净值一样的图即可（详细来定）」；②「K 线图和 vol 图可以左右移动时间和缩放，但是其他视图，比如净值、聚合总分、各策略评分等没有随着 K 线展示的时间范围改变显示」；③「L2 层交易明细还需要一个按钮，点击之后回测结果所有视图都跳转到对应交易的时间段」；④（补问）「L2 交易明细应该是有两个显式按钮的，一个是显示明细，一个是跳转」+「现在 K 线和其他视图的时间轴同步的逻辑是什么样的？」

## 2. 决策

### 2.1 D1｜持仓比率 = 引擎逐 bar 写下的**事实**（新可抽样曲线 kind）

- `BarRecord` 增持仓快照：`qty` / `position_value`（= `qty × bar.close`）/ `cash`（引擎在该点已同时持有两者，F16b）。
- 新增 `ResultKind::Position`，与 `net_value` 同级：**允许抽样，但必须披露**（`downsampled`/`original_bars`，沿用 ADR-024 D10）。不得混入 `fills` 的「禁止抽样」白名单语义。
- sim-live 侧在既有 net_value 生成点（`simlive.rs:807`）同步产出；**多标的聚合口径**：`position_value = Σ_code(qty × latest)`、`cash = 会话现金`、`nav = cash + position_value`。

**口径（冻结，禁止裸用"持仓比率"）**：

| 量 | 定义 | 分母/口径 |
|---|---|---|
| `position_value` | 持仓**市值**（bar close / latest 计价） | 时点值 |
| `nav` | `cash + position_value` | 与既有 net_value 逐点一致 |
| `position_ratio` | `position_value / nav`（`nav ≤ 0` ⇒ `0`） | **时点市值 / 时点净值** |
| `cash_ratio` | `1 − position_ratio`（并列披露，免用户自算） | 同上 |

**口径消歧（强制，固化 F20 的教训）**：`position_ratio`（**时点市值/时点净值**）与 ADR-026 的 `deployed_pct`（**区间累计敞口/初始资金**）、`cash_consumed_pct`（**区间累计资金占用/初始资金**）是**三个不同物**，必须在接口字段名、UI 标签、文档中**分别命名、分别注明分母**。特别是未满仓 run：`position_ratio` 是曲线，`deployed_pct` 是单值，二者**不得互相解释**。

### 2.2 D2｜结果页时间窗 = **页面级多源共享状态**

- 新增 `ResultWindowState { from_ts, to_ts, span_bars, source, rev }`，**页面级**持有（不是 ChartSyncGroup 内部私有态，因该组只同步 klinecharts 实例，F12）。
- **三个窗口来源**：① K 线交互（pan/zoom，leader 语义）；② **L1/L2 跳转**（程序化写入）；③ 「全览/重置」与「窗口历史回退」。
- **回声抑制**：程序化写窗后 K 线派发的 `onZoom`/`onScroll` **必须**被抑制（复用 F19 的 `programmaticScroll` 模式 + ADR-022 §2.3 的 `applying` 标志），并以 `rev` 单调序号防乱序覆盖。
- **窗口消费方**：K 线（`setBarSpace` + `scrollToTimestamp`；**必须**放宽该实例 `barSpaceLimit` 或改用 `scrollToDataIndex`，且**断言跳转成功**——F18 的静默失败零容忍）；SVG 曲线视图（按窗口取数）；持仓比率视图。

### 2.2b D2.1｜视图时间轴重建（Grill 补问二新增，**必须**；2026-09-20 根因修正）

现状是**三套互不认识的时间轴**（K 线视口 / 三条曲线的“下标轴” / 各自的取数范围），故“按窗口取数”**不足以**实现联动。必须同时建立三件事：

1. **ts→x 映射必须存在**：**新增** `mapLineByTs(pts, domainFrom, domainTo, …)`（**不改** `mapLine`，因它有 3 个既有调用点，F23）。
2. **对齐基准必须是 bar 索引空间（不是 ts 线性）—— 本 ADR 初版此条写错，现修正**：
   klinecharts 的 x 轴是**每根 bar 一槽**（午休/隔夜/周末等缺口被**折叠**），而 ts 线性映射会让两轴按缺口时间占比发散。
   **实测（M5，1949 根）**：相邻 ts 间隔 300s × 1871 / 5400s × 39（午休）/ 66600s × 31（隔夜）/ 239400s × 7（周末）；
   120 根窗口下 ts 线性 vs 索引线性最大偏差 **289.4 / 984 px**（≈ 29%），300 根 254.7 px，全览 46.1 px。
   ⇒ 正确做法：曲线点 `(ts, y)` 先经 **ts→bar 索引查表**得到索引 `i`，再以 `[window_from_idx, window_to_idx]` 为 x 定义域映射。
   查表源 = **K 线所绘制的同一 bar 序列**（已加载 bar 的 ts 数组）；不可得时回退 run 的 `per_bar` ts 序列，并**显式标注降级**（禁静默）。
3. **共享窗口状态需同时携带索引范围与 ts 范围**：索引范围（`from_idx`/`to_idx`）用于 x 映射，ts 范围用于 `/curve` 的 `from_ts`/`to_ts` 取数参数；两者必须同源同步，不得不同步。
4. 纯 ts 线性定义域仅作为**降级路径**保留（bar 序列不可得时），且必须在 UI 显式标注“时间轴降级（ts 线性，与 K 线可能存在缺口偏差）”。

### 2.2c D2.2｜K 线是**唯一视口权威**，曲线不得有独立默认域（2026-09-20 用户实测新增）

用户实测：净值/聚合总分/各策略评分**永远把最新 bar 固定在视图最右边**，与 K 线对不上——因为 K 线最后一个 bar **不固定**在右缘（可滚动/可留白）。

根因：曲线在无窗口时回退到「数据自身 min/max 扇伸满框」（`domain == null` 分支），等价于“首点贴左缘、末点贴右缘”，与 K 线的固定槽宽+可滚视口**不是同一个东西**。

**硬约束：**
1. 曲线视图**禁止**回退到数据自身 min/max 扇伸（除 D2.1 第 4 条的显式降级外，且降级不得静默）；
2. 窗口状态必须在初始化时就**从 K 线当前视口**取值（包括默认态、跟随最新态、全览态），不得等用户交互才建立；
3. 曲线与 K 线必须共用**同一绘图区几何**：除 bar 索引映射外，左/右内边距（K 线右侧留白、坐标轴宽度）也必须对齐，否则仍会有固定偏移（建议以同一 insets 参数化并断言）。

### 2.2d D2.3｜真渲染测量暴露的三项硬缺陷（2026-09-20，tester 六态实测）

证据：`tester/evidence/20260920_adr027_axis_align/report.md`（六态真渲染 + 缺口折叠模型交叉验证）。

1. **K 线可见区间 ≠ 发布出去的窗口（6 态中 5 态不相等）**：init 1.680×、300 根 1.309×、600 根 1.661×、对照 27×、全览 0.398×（仅 L2 跳转态 = 1.000×）。
   ⇒ 窗口必须**双向精确**：①K 线交互后发布的必须是引擎实际生效的可见范围（不是请求值）；②程序化写窗后**必须回读**并断言与请求一致，不一致就按实际值发布并**显式披露被钳位**（禁“请求即发布”）。
2. **曲线数据/定义域不同步（全览态仅渲染 89 点、占窗口 2.5% 并全部挤在右端）**：`/curve` 返回 1949 点而页面 polyline 仅 89 点。
   ⇒ **数据与定义域必须原子切换**：窗口变化后，新定义域只能在新数据到位（同 `rev`）后应用；旧数据 + 新域（或新数据 + 旧域）均禁止渲染，必须保持“加载中”态。
3. **全览的物理上限未披露**：klinecharts 单图上限（dataList 1000 根 + `barSpace ≥ 1` + 666px）⇒ 全览**物理上只能显示 614/1949 根（31.5%）**。
   ⇒ 全览必须重定义为「**尽可能全**」并**显式标注**「显示 N / 共 M 根（受渲染上限约束）」；曲线跟随**同一实际可见范围**，不得自行扇伸到全量。
4. 曲线右端距窗口右缘固定少 1 根（0.4~2.9 px@984）：并入第 1 项几何对齐一并消除。

### 2.2e D2.4｜曲线只画**评估段**：预热段（warmup）不参与分数曲线（2026-09-22 用户实测 + 决策 A）

- **现象**（用户截图取证，`coder/report/adr028_curve_y_scaling_mismatch_analysis.md` §0.0）：同屏四条曲线横向范围不一致 ——
  净值/持仓只占右侧 **≈17% / ≈12%**（左侧 80% 对比度增强后仍为纯背景），而聚合总分/各策略评分铺到 **≈83% / ≈85%**、K 线蜡烛满宽；
  用户判词：「**聚合和各策略评分的 scale 不对，净值是对的**」。
- **根因**（代码可查）：引擎在 warmup 段**仍逐 bar 评分**（`per_bar.scores/aggregate` 全量记录并标 `warmup`），但**不产净值/回撤/持仓**
  （`if !is_warmup` 才 push；`crates/strategy-core/src/engine.rs:937-959`）⇒ 四条曲线共享同一 x 轴（D2.1）时，
  两条分数曲线横跨预热段、价值类两条只覆盖执行段。前端此前**完全不知道预热段存在**（`WorkbenchBarRecord` 无 `warmup` 列）。
- **决策（用户 2026-09-22 选 A）**：**分数曲线不画预热段** —— 曲线数据裁到 run 的**评估区间** `[from_ts, to_ts]`
  （后端存 effective 区间 = in-range；`crates/application/src/workbench.rs:736,757`）。
  K 线卡本就取 `[run.from_ts, run.to_ts]` ⇒ 四条曲线与 K 线**同段对齐**。

**契约（硬约束）：**

1. **评估段** = run 的 effective `[from_ts, to_ts]`（Unix 秒）；边界**含**端点；**只按 `ts` 判定**（不依赖 `warmup` 列 ⇒ legacy/旧 run 同样成立）。
2. `from`/`to` 不可得、不可解析、或 `from > to` ⇒ **不裁剪**（坏数据不得静默清空曲线，`dropped = 0`）。
3. **禁止静默有损**（ADR-024 D10）：裁剪根数必须回传（`RunCurve.excludedWarmupBars`）并由 UI 标注
   「预热段 N 根不计入」；N 优先取后端 `config.warmup_effective`（精确根数），不可得时回退为裁掉的点数。
   脚注「共 N bar」的口径随之改为「**评估段** 共 M bar」。
4. **逐 bar 明细 / 事件日志（事实表）不裁**（预热段行保留；曲线才裁）。
5. **不新增/不改 `/curve` 请求参数**（仍按 D3 窗口语义）；裁剪在客户端派生层**单点**完成（`useRunSeries`）
   —— 不触碰冻结规格对「全览 ⇒ 不传窗口参数」的口径。
6. 预热段内的点**不得**再计入「N 点不在 K 线 bar 序列上（已剔除）」这一**配对失败**披露（两者语义不同：
   前者=按区间裁剪，后者=K 线 bar 序列不可配）。

`useRunSeries`（chunked 与 legacy 两条路径同口径）+

### 2.3 D3｜`/curve` 增时间窗参数（保真优先）

- 增 `from_ts`/`to_ts`（缺省 = 全区间 ⇒ **向后兼容**）；窗口内**重新采样** `k`；响应回显 `window_from_ts`/`window_to_ts`/`window_bars` + 既有 `downsampled`/`original_bars`。
- **节流**：窗口请求 ~200ms 节流，**以最后一次为准**（`rev` 丢弃在飞旧响应）。
- **禁止**用已取点前端裁剪替代（放大后点变稀 = 静默有损）；**禁止**窗口加载期间用旧数据静默顶替（F14/D11）。

### 2.4 D4｜L1/L2 的显式按钮与跳转定位（按钮语义 = 方案②）

**按钮布置（两层各两枚，取消隐式“点击整行展开”——架构默认，可否决）**：

| 层 | 按钮 | 语义 |
|---|---|---|
| **L1 行** | `[明细]` | 展开/收起该回合的 **L2 子列表**（懒加载，D8；按钮自带展开态 aria-expanded） |
| **L1 行** | `[跳转]` | 窗口 = 该回合 `[open_bar, close_bar]`（± 少量 buffer） |
| **L2 行** | `[明细]` | 展开该笔成交的**完整字段详情**（行内放不下的：`trade_value/commission/stamp_duty` 拆分、成交后双口径均价、`cum_*` 累计、sim 侧 lot 归属） |
| **L2 行** | `[跳转]` | 窗口 = 该笔成交 bar 为**中心**、默认 **120 根**（可配） |

- **取消隐式行点击**：不再用“点击整行”展开（避免与文本选中/复制冲突，且显式按钮可测、可禁、可加 tooltip）。
- **窗口历史栈** + 常驻「全览」按钮（多次跳转后可回退）。
- **sim-live 跨标的**：若目标成交属**另一标的**，跳转**切换 K 线标的并显式提示已切换**（禁止静默无效）。
- **跳转可达性**：L1/L2 跳转前必须验证目标 bar 落在已加载 K 线区间内；超出则先按区间取数再定位，**不得**静默失败（与 F18 同类纪律）。

### 2.4c D4.2｜结果页视图缩放与指标选择（2026-09-20 用户要求，全按推荐）

1. **复用看板**：K 线本体与副图指标选择**直接复用看板实现**（同一 `KlineChart` + `INDICATOR_DEFS` + Toolbar 指标勾选逻辑）；看板无对应实现的部分（手写 SVG 曲线卡）自研。

### 2.7 D7｜明细独立视图（上下分层）与「跳转不再把明细顶出视口」（2026-09-23 用户裁决 = 方案 B）

**触发**：用户要求「回测明细跳转之后还能继续看到明细，就是明细做成另外一个视图，不在 K 线/持仓比例等一组里」。取证：跳转把整页 `scrollTop` 从 1388 拉到 40、表体 `top 1592.7`（视口 800）⇒ `firstRowInView.visible=false`，而 K 线卡 `40..296` 完整可见。

**决策（结构）**：

1. **结果页改为上下分层**：**上栏** = K 线 + 窗口控制条 + 四张曲线卡（**保住全宽**，**上栏自身内部滚动**）；**下栏** = **明细视图**（独立滚动区）；**整页不再滚动**（页面级滚动被移除）。
2. **下栏内容 = 全部四块**：① L1 回合表 ② L2 逐笔成交 ③ 逐 bar 明细 ④ 事件日志；下栏内部用**分段控件/tab**，默认停在「回合与逐笔」。
3. **下栏尺寸**：默认 **40% 视口高**；**可拖拽分隔条**、**可折叠**（折叠后上栏占满）、比例**记忆**（同 2.6 第 3 条纪律）。
   **方向语义（2026-09-24 补：契约原本未写，导致实现与规格各自认定一个方向、两边都错）**：分隔条位于下栏**上沿** ⇒ **鼠标向上移动 ⇒ 下栏变高 / 上栏变矮**（`detailPx = startDetail − Δy`），**位移 1:1**（受 [0.15,0.85] 夹取与上栏保底 200px 约束）；**鼠标向下 ⇒ 下栏变矮**。**注意与卡片高度拖拽的方向相反**（卡片把手在**下沿**：`cardPx = startH + Δy`）——两者符号不同是几何决定的，**禁止**互相套用。双击分隔条复位 40%。
4. **跳转行为（B1-1 = 完全不动）**：跳转**不得**改变下栏滚动位置与内容；只**在上栏内部**把 K 线滚回可见 + 保留 D4.1 的目标高亮（标记放大 + 描边脉冲 3s）。
5. **契约/规格影响**：既有 `web/e2e/adr028-*.e2e.ts` 中依赖「单列布局 + 整页滚动」的断言（含 `wb-kline-focus-anchor` 的 `scrollIntoView` 语义）必须按新布局修订；`scrollIntoView` 的作用域收敛为「上栏容器内」。
6. **验收判据（真渲染，按视口分档；2026-09-23 实施期裁决修正）**：一次 L1 与一次 L2 跳转，前后对比必须满足 ①页面 `window.scrollY` 不变（页面无滚动容器）②下栏容器 `scrollTop` 不变 ③下栏内目标行**仍在**其容器视口内 ④K 线回到可见（见下分档）⑤上下栏各有稳定 testid 且分隔条可拖拽（比例变化 + 记忆生效）。
   - **物理约束（实测登记）**：上栏内容总量 ≈ 6524px（卡 520 + 窗口条 34 + 四张曲线卡 204/208/236/289）⇒ **任何视口下上栏都需自身滚动**；“520 整卡完整可见”仅在视口高 ≥ **实测标定阈值**（≈1050–1100px，须由实施期实测标定并落盘）时成立。旧基线卡高 256 时“整卡可见”属历史巧合，**不作为契约继承**。
   - **强档（视口 ≥ 阈值）**：**整卡可见 ∧ 下栏 40% 同时成立**（整卡 top/bottom 均在上栏容器视口内 + 与下栏零重叠 + ②③ 仍成立）；**e2e 须新增高视口用例**（如 1280×1400，接近用户真实视口）跑强档。
   - **弱档（视口 < 阈值）**：①上栏滚动后**卡顶或蜡烛主图顶与上栏视口顶对齐**②**蜡烛主图可见比 ≥ `required`**，其中 `cap = clamp01((上栏容器视口高 − 卡头实高) ÷ 主图高)`（**该视口下的物理可达上限**）、**`required = max(0.60, min(0.80, cap − 0.05))`**；规格**必须并列记录** cap / required / 实测比。语义：能达 0.80 时必须达 0.80；几何上达不到时按「对准可达上限」判（**0.60 硬地板**防「把面板压扁后门槛自动降低」；**禁止**把几何不可达写成绿或静默放宽）。实测校准：**1280×800** ⇒ cap≈1.0、required=0.80、实测 **0.909**（绿）；**1280×720**（e2e 默认 device）⇒ cap≈0.771（含高亮提示换行）、required≈0.721、实测 **0.773**（绿）。③**与下栏零重叠**④ ②③ 仍成立；e2e 在小视口（720/800）跑弱档。
   - **零新增产品口径（硬约束）**：不改 D7-3 的 40%、不改 D6-1 的 520，**禁止**按视口夹取下栏高度一类“同操作不同表现”的行为；物理约束仅作**文档事实**登记。

**明确不做（本次）**：不把明细做成独立路由页/切换 tab（与「同时可见」冲突，已排除）。

### 2.8 D8｜分隔条方向语义（§2.7-3 补遗；2026-09-24）

- **缺陷（用户实测）**：拖"明细视图高度"时方向反了（鼠标向上 ⇒ 下栏变矮）。
- **根因**：`useResultLayout.ts` 的 `nextPx = startDetail + Δy`（分隔条在下栏**上沿**，应为 `− Δy`）；**且既有 D7 规格把反方向当作正确**（`'拖 +90 ⇒ 下栏变高'`，而 `dragSplitter` 的 `dy` 正=向下）⇒ **契约缺口**（原文只写"可拖拽改变比例"，未定义方向）⇒ 实现/规格/独立探针三方各自认定了同一个错方向，判据只能验"变了"、不能验"变对"。
- **契约**：分隔条位于**其上方视图的下沿 / 下方视图的上沿** ⇒ **鼠标向上 ⇒ 上方视图变高、下方视图变矮**；位移 **1:1**（受比例 clamp 与相邻视图最小高约束）；**卡片类把手方向相反**（把手下沿：`startH + Δy`），**禁止互相套用**（几何决定）；双击分隔条 ⇒ 复位该边界默认比例。
- **验收**：方向 + 1:1 量纲 + 夹取 + 双击复位 + **两类把手符号相反**在同一规格内都有断言；判据须有鉴别力（在错符号实现上必红）。
- **状态（2026-09-24）**：**已实现**（`useResultLayout.ts` 单符号修复 + 注释）；新规格 `adr028-d8-splitter-direction.e2e.ts`（判据标签 D8-1..4）+ `useResultLayout.test.tsx`（5 例）；`adr028-d7-detail-split.e2e.ts` 方向断言按契约推导重锚；实现方变异反证已做（错符号⇒单测 5 红、D8 2 红、重锚 D7 1 红；复原 sha256 一致）；**独立复验进行中**。

### 2.9 D9｜结果页三视图拆分：K 线视图 / 指标视图 / 明细视图（2026-09-24 用户裁决，授权修订）

**诉求（用户原话）**：「把 K 线图也再单独提出来作为一个视图 ⇒ 上中下三个视图：上=K 线、中=指标、下=明细」；好处 =「看具体指标的时候都能和 K 线对应起来」；另需「收起明细的能力」。

**结构（硬约束）**
1. 三视图纵向：**上=K 线视图**（K 线卡 + 窗口控制条）、**中=指标视图**（**仅**四张曲线卡：聚合总分 / 各策略评分 / 净值+回撤 / 持仓比率）、**下=明细视图**（4 tab：回合与逐笔 / 8项绩效 / 逐 bar 明细 / 事件日志，**不拆**）。两条分隔条（K线↔指标、指标↔明细）。
2. **K 线视图常驻、不可收起**（它是 x 域锚）；**指标视图与明细视图各自可收起**：收起后**不留空**、其余视图按原比例分享释放空间；相邻处留**常驻可见、带视图名**的恢复条（如「指标 ▲ / 明细 ▲」——避免“收起来找不回”，D7 既有“收起”入口因可发现性差而未被用户发现）；收起态与比例均**记忆**。
   **收起态编辑语义（2026-09-24 裁决，补契约缺口）**：①**收起段的存储比例冻结**——拖拽**永不改写**收起段的比例（否则“收起再展开”会变矮，与“收起是可逆动作”相违）；②**拖拽不得是死控件**：收起态下拖**可见两段之间的边界** ⇒ 只在**可见两段之间** 1:1 重分配（把收起段那一份视为“不可分配”），两侧各受可读下限夹取且越界披露；③**展开** ⇒ 收起段回到**冻结比例**，可见两段**按比例收缩**（相对分配保持）；④判据：收起→拖→展开后 **收起段高回到收起前（±2px）** ∧ **可见两段相对比例保持（±2px）**。
3. **滚动语义**：K 线视图**不滚动**（K 线自带 pan/zoom）；指标视图与明细视图**各自内部滚动**；**整页仍不滚动**（延续 D7-1）。
4. **x 域**：**永远锚定“K 线可见 bar 序列”**（D2.1 单源语义**完全不变**）；因 K 线常驻，**不引入**锁定/降级规则（用户 Q4=C）。

**高度控制（取代 D6 的卡高机制；用户 Q1=B 授权）**
5. **视图高度取代卡片高度**：K 线高度 = K 线视图高度（卡片在视图内 `h-full`）。**删除**：D6 第 1 项（卡高默认 520 的**卡片**语义）、第 2 项（S/M/L 预设 260/420/560）、第 5 项（卡片下沿把手可发现性——规则**转移**到分隔条）、第 6 项（拖卡下沿/持久化/双击复位到卡片 ⇒ 改为拖分隔条/持久化/双击复位该边界）、第 7 项（`eestock.result.cardHeights.v1` 的**卡高**语义；旧值可作**一次性初始视图高度**迁移后弃用该键，迁移只读、且仅界内值采信）。
   **必修缺陷（2026-09-24 标定发现）**：**记忆路径绕过夹取**——实测播种 `{"kline":200}` 直接渲染 200 ⇒ 主图 **121px < 160 硬下限**（因挂载时尚未测到卡头/副图数，夹取用了默认下限 200）。D9 必须：视图高度从记忆恢复后，按**实测后的有效下限再夹取一次**（并在卡头/副图数变化时重夹），禁止任何路径把主图压到 160 以下。
6. **保留**（约束对象由“卡片高”改为“K 线视图高”；以下为 **2026-09-24 真身实测**值，代替草案的算术推导）：
   - 内部换算：`内层 = 卡高 − 卡头 20 − 卡边框 2`；`主图 = 内层 − x轴 26 − 分隔 1×副图数 − Σ副图` ⇒ **1 副图（VOL）`主图 = 卡高 − 149`**、**2 副图 `主图 = 卡高 − 170`**（Σ副图 = 100 / 120=60+60）；实测点 240→161、400→251、520→371、700→551。

   - **默认态主图判据（D9-8；2026-09-24 纠错后定案，四条）**：

   夹取优先级：**K 线有效下限 → 指标可读下限 → 明细可读下限**；三者之和 > 可用高时按比例压缩并**显式披露**（禁静默）。收起释放实测：**释放 = 明细高 − 2**（720:+286、800:+318、1400:+558），释放按原比例进入其余两段（无孤立空隙）。
   **「存储 == 生效」不变量（2026-09-24 裁决；根因级）**：任何会写盘的状态转换（**迁移 / 收起 / 展开 / 拖拽 / 键盘步进**）之后，落盘的 `ratios` **必须等于生效态**（= `planThreeViews` 夹取后的真实比例），**禁止存储不可行比例**。理由：`plan` 在夹取态下的渲染几何**不是比例集合的纯函数**（含 donor 结构）⇒ 一旦存了不可行比例，必然存在某条路径不可逆（本批两例同源：BLOCKED-1 的 `detail: 0` 与「收起段 39px 偏移」反例）。配套判据：任一转换后对每个**未收起**视图断言 `ratio_v × 可用高 ≥ min_v`（±1px）；**并覆盖冻结份额**：收起态必须满足 `S ≤ 1 − (Σ_可见 min)/可用高`（`S` = 收起段冻结比例之和），不满足时**把冻结份额收缩到该可行上界**（`S` 可被归一修改，但**永不为 0**）并置 `clamped` + **显式披露**（文案须说明"原收起比例在当前视口不可行，已收缩"）；即：**归一必须完备**——可见段与冻结份额两侧都要落在可行域内，否则必然出现"存储 ≠ 生效"（2026-09-24 独立复验的 legacy `v1{ratio:0.5,collapsed:true}` 在视口 <≈1045px 即此情形）。
8. **分隔条方向语义**：与 D8 一致（向上 ⇒ **上方**视图变高）；指标↔明细同规则；双击各自复位默认比例。
   **三视图高度均可调（2 自由度守恒；2026-09-24 用户确认）**：**两条分隔条覆盖三个视图**——K 线经 K线↔指标、指标经任一条（反向补偿）、明细经指标↔明细；**任一调整后 `klinePx + indicatorsPx + detailPx == 可用高`（±2px）**，且 **`可用高 + 2×分隔条(24) + 4×gap(16) == split 几何高`（±2px）**（`可用 = 视口 − 132` **已扣除**分隔条与 gap；2026-09-24 复验更正：两者同时成立，不得写成“Σ三段 + 分隔条 == 可用高”）；**双击分隔条 = 逐边界复位**（只动该边界两侧，**第三视图不动**，需有鉴别判据）。指标视图**不需要**第三个控件。因自由度只有 2，“三者各自独立取值”在几何上不可实现（总高固定），此守恒与夹取优先级（第 6 项）共同构成判据。

**契约/规格影响（本次必须重锚，按契约推导、禁按实现倒推）**

## 4. 验收口径

1. **窗口一致性**：K 线可见 bar 的集合 == 各曲线视图收到的窗口覆盖集合（允许 ≤1 根 bar 量化误差，同 ADR-022 §2.3）；**且各曲线视图的 x 映射必须基于同一 bar 索引序列**（禁 ts 线性作为主路，除非显式标注降级）。
   **像素级判据**：同一 ts 在 K 线与各曲线视图上的 x 坐标偏差 ≤ 2px（984px 参考宽度）；实测修复前 120 根窗口偏差 289.4px 即为失败基线。
   **度量口径（冻结，2026-09-20 裁决）**：偏差必须用**同一根 bar（或同一 ts）在两图上的 x 坐标配对**计算；**禁止**用「假设曲线按 ts 线性绘制」的反解公式（该假设在修复后已不成立，用它会把已对齐的图算成大偏差，属度量口径错误而非缺陷）。
   **窗口覆盖 ≠ 像素对齐**：窗口 = run 全区间时，K 线因渲染物理上限（dataList 1000 根 + `barSpace ≥ 1` + 面板像素）只能显示其中 N 根（实测 614/1949），此时**窗口覆盖比 < 1 是正确且预期的**；验收只看像素对齐与「显示 N / 共 M 根」披露是否到位。
   **默认态也适用**：页面首次渲染（未做任何 pan/zoom）时，曲线末点**不得**固定贴在右边缘，必须与 K 线末根 bar 同位置（含右侧留白）；K 线最后一个 bar 不在右缘时，曲线末点也不得在右缘。
8. **K 线尺寸（D6，真渲染判据）**：默认卡高 520px 时**蜡烛主图 ≥ 320px**、**副图合计 ≤ 120px**、**卡头 ≤ 48px**；卡高拖到 min 200px 时**主图 ≥ 160px**（clamp 生效）；把手**可命中带 ≥ 12px** 且**悬停有非透明背景变化**（判据须断言计算样式变化，不得只断言元素存在）；拖拽后卡高与 klinecharts 容器高**均**变化，刷新后保持，双击标题复位到 520。
9. **分层与跳转滚动（D7，真渲染判据）**：见 2.7 第 6 条四问（`scrollY` 不变 / 下栏 `scrollTop` 不变 / 目标行仍可见 / K 线卡完整可见），且须在**新默认卡高**下同时成立。
10. **盲区补齐（本次强制）**：既有 D4.2/D5 规格的 5 项盲区中，**①蜡烛主图高与卡头高**、**②跳转后明细可见性** 必须在本次转为正式判据；**③标记遮挡率**、**④跳转 scale 与回执自洽性**、**⑤跳转后曲线是否为空** 本次仅登记（见 §5），但**测量口径必须先建好**（复用 `20260923_result_ux_probe` 的量化方法），以免下次再以「未测」收场。
11. **D8（分隔条方向语义，真渲染判据）**：上拖 −N ⇒ 下栏高 +N（±2px；N ∈ {40,120,240} 至少三组）；下拖 +N ⇒ −N；比例夹取 0.15/0.85 与相邻视图最小高约束生效；双击分隔条 ⇒ 复位默认比例；**两类把手符号相反**（卡片把手下拖 ⇒ 卡片变高）亦须有断言；判据须在错符号实现上**必红**。
12. **D9（三视图）**：需先由 tester **真身标定**后填入具体数值，至少覆盖：①三段比例默认值与夹取优先级（K 线有效下限 / 指标与明细各自最小高）② **主图判据**按 §2.9-6 的四条（恒等式 / 硬不变量 / 分档：几何可行断言 320、不可行断言“K 线优先吃满” + `data-view-clamped` 披露 / 作废旧口径并落盘实测） ③指标视图与明细视图各自可收起（收起后不留空、恢复条常驻可点、比例记忆、收起态记忆）④**K 线视图不可收起**（无收起入口，断言其缺失）⑤两个分隔条的方向语义与双击复位 ⑥切视图/收起/展开**不得改变另一侧的滚动位置**（对齐 D7-4② 的纪律）⑦既有 D6/D7 全量判据在**新结构**下重新取证（含 x 域与像素对齐 D2.1/D2.3-4 不得退化）。
2. **跳转确定性**：L2 定位后窗口中心 bar == 该成交 `bar_index`；L1 定位后窗口 == 回合区间；**且 `setBarSpace` 未被静默吞掉**（断言）；目标 bar 未加载时先取数再定位，无静默失败。
3. **持仓比率恒等式**（逐点）：`position_value + cash == nav`，且 `position_ratio × nav == position_value`（容差显式声明）。
4. **节流后最终一致**：连续 pan/zoom 结束后，最终窗口与最后一次请求一致（无乱序覆盖）。
5. **口径不混用**：`position_ratio` 与 `deployed_pct`/`cash_consumed_pct` 在同屏出现时，三者标签各含分母说明。
6. **多标的**：sim-live 跨标的跳转切主图并出现显式提示。
7. **按钮可测**：L1/L2 四枚按钮均有稳定 testid 与 `aria-expanded` 状态断言；取消隐式行点击后，点击行内文本不得触发展开/跳转。

  再进契约」，且**标定方与判据起草方应为不同角色**（本批正是实施车道在动工前发现契约不自洽，
