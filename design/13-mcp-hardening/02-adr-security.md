# 13-mcp-hardening / 02 — MCP 通道安全 ADR（I-9）

> 状态：已按用户 2026-09-12「全按推荐进行」批准（D7）。本文只界定**安全边界与约束**，
> 不含实现工期承诺；TLS/鉴权/网关的落地实现另立 ADR。

## 1. 现状事实（实测）

| 事实 | 证据 |
|---|---|
| MCP 明文 SSE，无鉴权 | GET :8082/sse 直接返回 `event: endpoint` + sessionId |
| 端口分离：8081 Web/REST、8082 MCP、8080 另占 | `ss -ltnp` 实测 |
| 端口绑定 0.0.0.0（非 loopback） | `ss` 显示 `0.0.0.0:8081/8082` |
| MCP gateway 拒绝非 loopback 客户端 | 外部 agent 报告（自建 TCP 中继 `/tmp/relay.py 18082 → 8082`） |
| 无 OpenAPI/schema 发布通道 | agent 报告；schema 仅能从 `tools/list` 运行时取 |

## 2. 风险判定

- 当前为**内网研发环境**（ADR-010 免认证前提），单机单用户，风险敞口可接受。
- 真正的风险不是"被外部攻击"，而是**边界模糊导致的误用**：
  ①0.0.0.0 绑定使同网段任何主机可直连下单类工具（`sim_place_order`）；
  ②无鉴权 + 明文使"谁在调用/调用了什么"不可审计；
  ③三端口分离无文档化契约，调用方靠试探（本次 I-4/I-9 即由此产生）。

## 3. 决议

| # | 决议 | 理由 |
|---|---|---|
| S1 | **`loopback-only` 作为显式设计约束**：8081/8082 应绑定 127.0.0.1（当前 0.0.0.0 属实现偏差，列入待修） | 消除同网段直连下单面 |
| S2 | **跨机访问必须经显式中继**（如 SSH 隧道），禁止裸暴露；中继为**使用方责任**，平台不提供 | 保持平台面最小 |
| S3 | **交易类工具（`sim_*` 下单/撤单）保持独立开关**，默认关闭 | 已有机制，明确写入文档 |
| S4 | 本批**不做** TLS / Token 鉴权 / OpenAPI 发布 | 夹带会放大改动面；内网前提下收益低于风险 |
| S5 | 三项各**另立 ADR**：TLS+鉴权、OpenAPI/schema 发布、端口收敛（三端口→单入口） | 每项都是架构级变更，须独立评估 |
| S6 | 文档化：`design/07-app-plane/01-mcp.md` 增加「安全边界与部署约束」章节（含 S1-S3） | 边界显式化治本 |

## 4. 待办（派生）

- **M-1（本批）**：端口绑定改为 loopback-only（可配置，默认 127.0.0.1）+ 文档章节。⚠️ 变更会中断跨机/替代端口联调，需在部署文档写明如何显式开启 0.0.0.0。
- **M-2（另立 ADR）**：Token 鉴权 + TLS（若未来脱离内网）。
- **M-3（另立 ADR）**：OpenAPI/schema 发布通道。
- **M-4（另立 ADR）**：端口收敛/统一入口。

## 5. 红线

- 不得为「方便联调」而长期裸绑 0.0.0.0；替代端口实例用后必须拆除（已有两次事故记录）。
