## 布局表达规范（三层法，2026-09-03 定为 web 文档标准，用户批准）

每页文档的布局节必须按四层表达，职责单一、逐层细化（样板：01-dashboard.md）：

### L1 ASCII 线框（空间骨架）

- 纯文本盒图，一目了然表达区域划分、尺寸约束（px 或 flex）、包含关系
- 约定：宽度标 `W=`、高度标 `H=`、弹性区标 `flex-1`；多视图模式（如宫格）各画一幅
- 全局约束线下注明（如 `min-width: 1280px`）

### L1.5 可视化样机（静态 HTML，tangle 生成，浏览器直接打开）

- 代码块 `file=design/06-web/preview/<页码>-<页名>.html`，零依赖单文件（内联 CSS/SVG）
- 职责：给**非前端人员**看布局效果——区域划分、尺寸比例、信息密度、红涨绿跌等着色约定
- 每区域左上角标灰色小标签注明区域 id；多视图模式各画一个画框；文末注明「样机非视觉设计稿」
- 风格基线：**现代深色交易终端风**（以 01-dashboard 样机为准——深色底 #0b0e17、霓虹涨红跌绿（#ff5c6c/#00e0a4）、玻璃拟态圆角卡片、青→紫渐变强调色、等宽数字），布局信息优先但不追求视觉细节

### L2 区域规格表（数据契约与状态机）

每个命名区域一行，列为固定六列：

| 区域 id | 内容 | 数据源 | loading/空/错误态 | 交互 |

- 区域 id 用 kebab-case，与 L1 线框、L3 骨架的 `data-region` 锚点**三者必须一一对应**
- 数据源注明 REST 端点 / WS topic / 客户端计算
- 状态三件套（loading/空/错误）不允许留空，无内容态也要写「不可能空（理由）」

### L3 布局骨架代码块（tangle 生成，文学式纪律延伸）
- 代码块 `file=web/src/layouts/<Page>Grid.tsx`，由 entangled 单向生成**带接线的结构骨架**
- 骨架职责边界（四类信息必须齐备）：
  1. **Props 接口**：页面需要的数据与回调签名（类型级契约）
  2. **区域 → 组件映射**：每个 data-region 锚点内注明承接组件（`<SymbolList/>` 等）
  3. **每区域内联注释**：数据源（REST/WS/客户端计算）+ 三态口径，与 L2 表一致
  4. **已定稿默认值**：默认周期/默认开关等决策值直接写成代码常量，不再散落散文
- **视觉样式（颜色/间距细节/hover 等）与数据获取实现手写于组件内**，不进骨架
- 改布局/改接线 = 改本文档 L3 代码块再 tangle，禁止手改生成的骨架文件
