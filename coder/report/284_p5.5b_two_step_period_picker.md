## 2. 功能与护栏实现说明

### 2.1 两步流程（`multiPeriodPicker.tsx`）
- **步骤 1**：`MULTI_PERIOD_PICKER_PERIODS = ['1m','5m','15m','1h','1d','1w']`（全集 \ {`1mo`}，秩升序）。
- **步骤 2**：`indicatorPeriodOptions(base)` = `{P | rank(P) ≥ rank(base)}`（**允许相等**）\ {`1mo`}；
  `1w` 在 `base < 1d` 时**出现但 `enabled=false` 且 `reason` 非空**（`1w 需基准 ≥ 1d（避免恒退化）`）——
  不得静默消失。改变步骤 1 ⇒ 由 `useEffect([options])` **立即收窄**候选并丢弃不再合法的已选项（02-spec §2.3）。
- **上限 3**：`MAX_INDICATOR_PERIODS = 3`（总周期 ≤4）；选满后其余候选 `disabled` 且给出原因。
- **实时提示**（`[data-mp-picker-hint]`）：候选收窄基准、已选 `n/3`、总 pane `x/12` 与**剩余 pane 预算**。
- **就地拒绝**：确认前跑 `validatePickerSelection`（与后端 7 条校验 + §7.4 pane 预算同口径，**去重计数**）；
  非法 ⇒ 写 `[data-testid="mp-picker-error"]`（非空文案、含被拒维度名）且**不发请求**（不静默截断）。
- **失败可见**：`onConfirm` 返回 Promise ⇒ `await`；reject ⇒ 可见报错且**保持打开（可重试）**。

### 2.2 提交语义 + `basePeriodOverridden` 消除（`DashboardPage.confirmMultiPeriodPicker`）
```
heights = heightsForSelection({base, indicatorPeriods}, 当前 heights)   // 键随周期增删
periods = Object.keys(heights)                                          // = [基准, ...指标周期]（去重 + 秩升序）
① 乐观：mpStore.applyServerConfig({enabled:true, periods, heights, indicators})  // 写 periods[0]
       + store.setPeriod(基准)                                                   // 同时写 state.period（原子批量）
② PUT /api/config/multi_period
③ 成功 ⇒ 采用服务端回显；失败 ⇒ 回滚配置 + 回滚工具栏周期 + rethrow（选择器显示可见报错）
```
`basePeriodDerivation(enabled, periods, toolbarPeriod)` 现要求 `overridden = enabled && periods.length > 1 && periods[0] !== toolbarPeriod`（02-spec §2.1 专项裁定）。
⇒ 双写后 `periods[0] === state.period` ⇒ `overridden=false`、`basePeriodSource='toolbar'`、`[data-mp-base-override]` 徽标**消失**。
`resolveBasePeriod` 为其唯一读处（单一权威，无静默不一致）。

### 2.3 heights 维护
`heightsForSelection`：输出键 = 去重后的 `[base, ...indicatorPeriods]`；保留既有键值；新增基准 ⇒ 420、新增卫星 ⇒ 180；
移除周期 ⇒ **删键（零残键）**。不触碰 P5 的分配/拖拽/持久化契约（`MultiPeriodChartStack` 未改）。

### 2.4 宫格护栏（§7.1「仅单图可用」）
- `multiPeriodUsable = gridMode === 'single'`；宫格模式 ⇒ **Toolbar 多周期区域整体隐藏**（开关 + 选择器入口）。
- 宫格模式 `satellites` 恒 `[]`（条件加 `gridMode !== 'single'`），且基准周期**不被配置覆盖**（走 `state.period`）
  ⇒ 不会以 `periods[0]` 残留基准/卫星周期的 WS 订阅与取数（C4 钉死）。

## 6. 需父级知悉的实现决定（非架构扩张，为设计强制后果）
- **`MultiPeriodState` 移除 `basePeriodOverridden` / `basePeriodSource` 两个快照字段**：它们现在必须比较
  `periods[0]` 与 `state.period`，而 `state.period` 属 `DashboardStore`（多周期 store 不持该数据流）⇒ 存快照会
  让覆盖态**永远为 true**（徽标永不消失，正是 §2.1 要消除的静默不一致）。故改由 `resolveBasePeriod(state, toolbarPeriod)`
  在**读处**现算（返回值 `overridden`/`source` 不变）。无任何测试/代码消费被移除字段（已全仓 grep 确认）。
- **选择器打开时步骤 2 初选为空**（页面传入 `basePeriod` + `indicators`，不预填 `indicatorPeriods`）：保证「两步流程」
  每次都从"选基准 → 选指标"开始；`indicatorPeriods` 作为受控初值 prop 仍受支持（C6 的 `chooseAndConfirm` 语义钉死：
  点击候选 = 选中该项）。
