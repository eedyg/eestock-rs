# 定投策略族（DCA Family）设计文档 v1

> 平台：eestock 统一策略系统（QuickJS 插件 + ExecutionPolicy）
> 状态：设计已定，进入编码
> 日期：2026-09-11

## 1. 目标

为「定投」这一投资纪律建立可回测、可复现、可对比的策略族，并把
「假设 → 插件 → 试算 → 发布 → 回测 → 对比 → 沉淀」整条链路跑通。

用户裁决：**三个择时内核各实现一版**（均线偏离 / 回撤触发 / 定期不定额），
外加一个无择时对照组，共 4 个插件。

## 2. 平台契约（决定了设计空间）

| 契约 | 含义 | 设计后果 |
|---|---|---|
| 插件每 bar 返回 0~100 分 | ≥60 买，≤40 卖，40~60 观望 | 只能表达三态（买/观望/卖），**没有连续仓位** |
| 批次由 DCA Policy 管 | `{tranches, mode: Equal\|FixedAmount, amount, interval}` | 插件不能决定"投多少"，只能决定"何时待在买入区" |
| Buy 信号中断 → 剩余批次作废 | 信号连续性 = 投入连续性 | 「投完就停」= 主动回中立分，天然停止加仓 |
| Buy 重现 → 批次重新计数 | 可以反复开新一轮 | 「越跌越买」= 条件满足就重新给高分 |
| 冷启动 | 指标在区间起点无预热，前 N 根返回 null | 回测前 `ma_n` 根为中立，属固有损耗 |
| 沙箱禁 Date/random/网络/文件 | 必须确定性 | 节奏只能靠 `ctx.index` 算术或模块级状态 |
| 有状态必须 save()/load() | 快照/重放一致 | 回撤触发版必须实现快照 |

### 2.1 关于「不定额」的表达边界

DCA Policy 每批金额固定，插件无法改变单批金额。因此「不定额」只能通过两条
通道近似表达，本设计如实采用并在此声明：

1. **跳过某些周期的批次**（少投）—— 直接有效；
2. **延长买入区窗口**（多投）—— 在 `tranches` 未耗尽时窗口越长、投的批数越多；
   一旦 `tranches` 耗尽则窗口无效。

这是平台能力的真实边界，不做假装。

## 3. 统一约定

- 分数语义：`85~90` 极强买入 / `75~80` 买入区 / `50` 中立 / `45` 观望（不投但不卖）
- **不使用卖出区（≤40）**：定投策略不做空、不主动清仓，退出交给运行级硬止损
  （`stop`）。理由：定投的价值来自长期筹码积累，插件层面的卖出信号会与
  "越跌越买"的内核直接冲突。
- 参数一律 snake_case，`PARAMS_SCHEMA` 声明 int/float。
- 批次窗口统一叫 `plan_bars`。

## 4. 四个插件规格

### 4.1 `dca_ma_dev` — 均线偏离分档定投（无状态）

假设：**收盘价相对长均线的负偏离是估值便宜的廉价代理**。跌得越深越买，
涨过均线就停投。

```
输入: dev = close / MA(ma_n) - 1

若 持仓 且 bars_since_entry < plan_bars   → 80   （本轮批次未投完，保持买入区）
否则:
    dev ≤ -dev_deep   → 85   （深度便宜）
    dev ≤ -dev_open   → 75   （浅度便宜）
    dev >  stop_dev   → 45   （贵，本期不投，但不卖）
    其他               → 50   （中立）
```

参数：`ma_n=60, dev_open=0.03, dev_deep=0.08, stop_dev=0.02, plan_bars=10`
状态：无 → 不需要 save/load。

### 4.2 `dca_drawdown` — 回撤触发定投（有状态）

假设：**从近期高点回撤足够深，是比均线偏离更直接的风险释放信号**。

```
peak = max(high[过去 win 根], 不含当前根)   ← 排除当前根避免自破位
dd   = close / peak - 1

若 持仓 且 bars_since_entry < plan_bars  → 80
否则:
    dd ≤ -dd_deep → 90
    dd ≤ -dd_open → 78
    其他          → 50
```

参数：`win=120, dd_open=0.10, dd_deep=0.20, plan_bars=10`
状态：滚动高点窗口 → **必须实现 save()/load()**，load 做防御性判空。

### 4.3 `dca_periodic` — 定期不定额

假设：**纪律性定投 + 只做减法**——按时投，但贵的时候跳过本期，超卖时延长投入窗口。

```
触发: (ctx.index % cadence) == 0         ← 用 bar 序号算术，无状态

barsSinceTrigger = index - floor(index/cadence)*cadence
若 barsSinceTrigger < plan_bars        → 80   （基础投批窗口）
若 barsSinceTrigger < boost_bars 且 RSI ≤ rsi_boost → 85 （超卖，延长窗口）
若非触发期                             → 50
触发期:
    RSI ≥ rsi_skip → 45 （贵，跳过本期）
    RSI ≤ rsi_boost → 88 （超卖）
    其他            → 75
```

参数：`cadence=20, plan_bars=5, boost_bars=15, rsi_n=14, rsi_skip=70, rsi_boost=30`
状态：无（全靠 `ctx.index` 算术）→ 不需要 save/load。

### 4.4 `dca_baseline` — 无脑定期定额（对照组，非策略）

```
barsSinceTrigger = index - floor(index/cadence)*cadence
barsSinceTrigger < plan_bars → 75
其他                          → 50
```

参数：`cadence=20, plan_bars=5`
作用：**这是判断三个策略是否真有价值的唯一标尺**。没有它，任何收益数字都无法解释。

## 5. 实验设计

### 5.1 多周期矩阵

参数以**自然交易日**为单位声明，再按实际周期的「每日 bar 数」换算成 bar 数
（`D1 = 1 bar/日`，`M15 = 16 bar/日`，A 股 4 小时 / 15 分钟）。这样才能把同一个
策略意图放到不同周期上而不静默改变语义。

| 预设 | 周期 | 窗口 | 定投节奏 | plan | MA | 回撤窗 | boost |
|---|---|---|---|---|---|---|---|
| `d1_monthly` | D1 | 4 年 | 20 日（≈月频） | 5 日 | 60 日 | 120 日 | 15 日 |
| `d1_weekly` | D1 | 4 年 | 5 日（周频） | 2 日 | 20 日 | 60 日 | 8 日 |
| `m15_daily` | M15 | 936 bar | 1 日（日频） | 0.25 日 | 10 日 | 20 日 | 4 日 |
| `h1_eq` | M15×4 | 936 bar | 5 日（周频） | 1.25 日 | 15 日 | 20 日 | 4 日 |

**1h 的处理（重要）**：引擎周期枚举实测只有 `M1/M5/M15/D1`，传 `1h` 直接报
`period 须为 M1/M5/M15/D1`；而 `get_kline` 能取到 1h K 线（覆盖约 8 个月）。
因此 1h 无法作为回测周期。`h1_eq` 预设用 **M15 承载、按 1h 视角设计自然周期**
作为近似实现——MA / Wilder RSI 的 bar 缩放关系（`alpha = 1/n`）保证两者在
长度等价时行为近似，但 M15 收盘序列的聚合方式与真实 1h 收盘不同，
**这是近似，不是等价**，结论中会显式标注。

### 5.2 标的

- `518880` 华安黄金易ETF（低波商品）
- `588000` 华夏科创50ETF（高波权益）

同一策略在两种波动环境下是否成立，是这个实验的核心问题。

### 5.3 成本与执行

- 成本：`rate_pct=0.025, min_fee=5.0, slippage_bp=2.0, stamp_duty_pct=0`
  —— ETF 必须把印花税钉为 0，默认 0.05 是股票口径。
- 执行：DCA Policy `{tranches:3, mode:"Equal", interval:5}`。
- 注意：`strategy_test_run` **没有费用参数**，其 sim_position 固定用 LumpSum
  且固定含 0.05% 印花税（实测 `stamp_duty` 字段 = 成交额 × 0.0005）。
  所以**试算只能验证行为，绩效评估必须走 `bt_run_ensemble`**。

### 5.4 对照臂


| 编号 | 配置 | 作用 |
|---|---|---|
| R1 | dca_baseline + DCA | 无择时定期定额（主标尺） |
| R2 | dca_ma_dev + DCA | 候选① |
| R3 | dca_drawdown + DCA | 候选② |
| R4 | dca_periodic + DCA | 候选③ |
| R5 | dca_baseline + LumpSum(1.0) | 一次性满仓（市场基准） |

## 6. 验收标准（通过线）

1. 三个候选策略各自**至少一个**指标显著优于 R1（年化 或 最大回撤 或 夏普）；
2. 且不能出现"收益略好但回撤爆炸"或"回撤略好但年化崩塌"的单边恶化；
3. 结论必须在**两个标的上都成立**才认为策略稳健；只在单标的上成立 → 记为
   "环境依赖"，如实报告，不包装成结论；
4. 全部结论必须附 `run_id` 与 sha256，可复现。

## 7. 已知边界（不做假装）

- 冷启动：区间前 `ma_n` / `win` 根无信号，属固有损耗。
- 单批金额不可变 → 「不定额」只能靠跳过/延长窗口近似（见 §2.1）。
- 无卖出逻辑 → 本族策略在单边下跌市中会持续买入，风险由运行级硬止损兜底，
  本轮实验不开硬止损，以便观察裸策略行为。
- 平台日线数据起点为 2022-07-31，无法覆盖更早的牛熊完整周期。
- **1h 不是合法回测周期**（见 §5.1），只能以 M15 近似。
- **M15 窗口实际只有 936 bar（≈2.4 个月）**，不是规则允许的 93 天：
  `get_kline` 单次上限 1000 根，93 天会产出 1170 根，导致无法做逐 bar 对齐校验。
  这是测试可行性约束，牺牲了约 20% 的 M15 样本。
- **常见宽基未注册**：`510300 / 510500 / 159915 / 513100` 等不在注册表内，
  查询它们返回 0 根 K 线而**不报错**（静默空数据）。可用标的只有注册表里的 44 只。

## 8. 验证手段（TDD 的可执行规格）

`tools/strategy_eval.py` 把本设计的规格变成可执行断言：

| 编号 | 断言 | 意义 |
|---|---|---|
| T1 | 评分 ∈ [0,100] 且有限 | 契约合规 |
| T2 | 两次试算逐 bar 相同 | 确定性 |
| T3 | 与 Python 独立复现逐 bar 一致 | **规格没有被实现偷改** |
| T4 | sim_position 真的产生成交 | 分数确实驱动得了执行 |
| T5 | 全序列无卖出区分数 | 设计红线（定投族不主动清仓） |

另有 **RSI oracle 自检**：用探针插件（直接返回宿主 `rsi`）反查宿主 RSI 口径，
只有它与本地 Wilder 实现逐 bar 一致，`dca_periodic` 的 T3 才可信。
实测：D1 999/999 bar、M15 936/936 bar 精确一致。

当参考实现显示「本窗口内触发条件从未成立」时，T4 记为 **SKIP（无机会）**
而不是 FAIL——因为 T3 已证明插件与规格一致，此时「无成交」是市场没机会，
不是插件坏了。这类 SKIP 本身是实验结论，必须如实报告。
