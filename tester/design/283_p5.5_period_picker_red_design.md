| 层 | 载体 | 覆盖内容 | 为什么需要该层 |
|---|---|---|---|

## 2. 接口契约（实现方必须满足；本文件 + 红测试共同钉死）

### 2.1 纯函数导出（`multiPeriodPicker.tsx`）

```ts
/** 步骤 1 全集 = 全部周期 \ {1mo}（ADR-022 §2.5；顺序 = 周期秩升序）。 */
export const MULTI_PERIOD_PICKER_PERIODS: Period[];              // ['1m','5m','15m','1h','1d','1w']
/** 指标周期上限（总周期 ≤4；ADR-022 口径 2）。 */
export const MAX_INDICATOR_PERIODS: number;                      // 3

/** 步骤 2 候选：`{P ∈ 全集 | rank(P) ≥ rank(base)}`；1w 在 base < 1d 时**出现但 enabled=false 且 reason 非空**。 */
export function indicatorPeriodOptions(base: Period): Array<{ period: Period; enabled: boolean; reason: string | null }>;

/** 总 pane 数 = 1 + 卫星数 × |去重后 indicators|（02-spec §7.4：**必须按去重集合计数**）。 */
export function multiPeriodPaneCount(periods: readonly string[], indicators: readonly string[]): number;

/** 选择器内校验（纯函数，与后端 7 条校验同口径）：ok=false ⇒ issues 至少一条含被拒维度名。 */
export function validatePickerSelection(input: {
  base: Period; indicatorPeriods: readonly Period[]; indicators: readonly string[];
}): { ok: boolean; issues: Array<{ dimension: 'periods' | 'heights' | 'indicators' | 'pane'; message: string }> };

/** heights 键随 periods 增删：保留既有键值；新增基准 ⇒ 420、新增卫星 ⇒ 180；移除周期 ⇒ 删除键（零残键）。 */
export function heightsForSelection(
  sel: { base: Period; indicatorPeriods: readonly Period[] },
  prevHeights: Record<string, number>,
): Record<string, number>;
```

### 2.2 组件 props（受控、无副作用；持久化由页面负责）

```ts
export interface MultiPeriodPeriodPickerProps {
  basePeriod: Period;                  // 步骤 1 初值（= 当前 K 线周期）
  indicatorPeriods?: Period[];         // 步骤 2 初值（= 配置 periods[1..]）
  indicators?: string[];               // 卫星指标集合（首版 ['dcap']）
  onConfirm(sel: { basePeriod: Period; indicatorPeriods: Period[] }): void | Promise<void>;
  onCancel?(): void;
}
```
- `onConfirm` 返回 Promise ⇒ 选择器 **await**；**reject ⇒ 必须可见报错**（`[data-testid="mp-picker-error"]`）且**保持打开**（可重试）；**不得静默关闭/静默截断**。
- 步骤 1 选择变化 ⇒ 步骤 2 候选集**立即**收窄（不得保留非法已选项）。

### 2.3 DOM 契约（jsdom/e2e 共用；全部为稳定数据属性，不依赖文案样式）

| 元素 | 选择器 | 语义 |
|---|---|---|
| 选择器根 | `[data-testid="mp-picker"]` | 打开态存在 |
| 步骤 1 选项 | `button[data-mp-base-period="<P>"]` | 全集 \ {1mo}；选中 ⇒ `aria-pressed="true"` |
| 步骤 2 选项 | `button[data-mp-indicator-period="<P>"]` | 候选；不可选 ⇒ `disabled` |
| 步骤 2 禁用原因 | `[data-mp-indicator-reason="<P>"]` | 非空文本（1w 条件 / 达上限 3 / 其它） |
| 确认 | `button[data-testid="mp-picker-confirm"]` | 提交选择 |
| 选择器错误 | `[data-testid="mp-picker-error"]` | onConfirm reject / 400 ⇒ 非空文案 |
| 页面入口 | `button[data-testid="mp-periods-open"]` | 单图 + 启用多周期时存在；点击打开选择器 |

### 2.4 页面层提交语义（本设计给实现方的硬口径）

确认（`onConfirm`）后页面必须**原子地**：
1. 计算 `periods = [base, ...indicatorPeriods]`（秩升序、去重）与 `heights = heightsForSelection(...)`；
2. **乐观**写 `multiPeriodStore`（`enabled=true` + periods + heights）**并且** `store.setPeriod(base)` —— 这是 §2.1「选择器落地时同时写 `periods[0]` 与 `state.period`」的直接要求；
3. `PUT /api/config/multi_period`；成功 ⇒ 采用服务端回显；失败 ⇒ **回滚**（配置 + 工具栏周期 + 保持选择器打开并显示错误）。
4. 目录口径影响：`multiPeriodStore.basePeriodDerivation` 的 **`basePeriodOverridden` 必须同时比较 `periods[0]` 与 `state.period`**
   （`overridden = enabled && periods.length > 1 && periods[0] !== state.period`）——否则提交后覆盖态仍为 true，
   §2.1 的「可观测不一致」永远无法消除。既有 `L5-2`（配置 `periods[0]='1m'` vs 工具栏 `15m`）在该口径下**仍绿**。
   - 页面可观测形式：`[data-mp-satellite].data-mp-base-period-source`（`config`|`toolbar`）+ `[data-mp-base-override]` 徽标仅在 `config` 时出现。

### 2.5 模式与零残留（§7.1/§7.5）
- 宫格模式（`grid2x2`/`grid2x3`）⇒ 多周期入口**隐藏或强制关闭**（若入口仍在，`aria-pressed` 必须为 `false`）、**零卫星**、**零卫星周期 WS 订阅**；
- 关闭开关 ⇒ 仅剩工具栏周期订阅、卫星周期**不得再取数**（计数冻结）、卫星 DOM 归零。
