## 2. 判据：log-log 斜率

### 2.1 全域拟合（矩阵 1k/5k/20k/50k/200k，单点中位）

| 系列 | 全域 slope（1k…200k） | rms_resid(log) |
|---|---|---|
| dual_ma, 1 slot | **1.568** | 0.326 |
| dual_ma, 3 slots | **1.572** | 0.333 |

> **低于 1.8–2.2 判据带**。原因可量化（非噪声）：

| 局部斜率（相邻点） | 1 slot | 3 slots |
|---|---|---|
| 1k → 5k | 1.113 | 1.096 |
| 5k → 20k | 1.554 | 1.576 |
| 20k → 50k | **1.849** | **1.853** |
| 50k → 200k | **1.895** | **1.898** |

小 n 处斜率 ≈1.0~1.1（**线性项主导**：每 bar 固定成本 b ≈ 3.8 µs/bar = 上下文/JS 对象构造），
随 n 增大斜率单调升到 **1.85–1.90**（二次项主导）。**单一幂律在跨 200 倍 n 区间不成立**，
故全域拟合被小 n 段拉低 —— 这是「两项模型」的直接证据，不是诊断不成立。

### 2.2 渐近拟合（判据的正确落点：大 n 段 = 二次项主导段）

| 系列 | 拟合区间 | slope | rms_resid(log) |
|---|---|---|---|
| dual_ma, 1 slot | n ≥ 20k（3 点） | **1.878** | 0.0117 |
| dual_ma, 1 slot | n ≥ 50k（2 点） | **1.895** | 0.0000 |
| dual_ma, 3 slots | n ≥ 20k（3 点） | **1.882** | 0.0115 |
| dual_ma, 3 slots | n ≥ 50k（2 点） | **1.898** | 0.0000 |
| **ctrl（隔离探针）, 1 slot** | **20k → 200k（2 点）** | **1.900** | **0.0000** |
| 附加点 1 slot | 15k → 290k | 1.892 | 0.0000 |
| 附加点 3 slots | 15k → 290k | 1.895 | 0.0000 |

**结论（判据）**：改造前 asymptotic log-log 斜率 = **1.878 – 1.900**，落在判据带
**1.8–2.2** 内 ⇒ **ADR §2.2「引擎 O(n²)」诊断成立**。（全域 1.57 已如实列出，其偏离原因见 §2.1；
若架构师要求以「全域单幂律」为判据，则该判据本身与数据生成过程不符，需改判据为「渐近斜率」。）

### 2.3 二次项指纹：t/n² 收敛

`t/n²`（s/bar²）逐点：1 slot **4.00e-9 → 9.60e-10 → 5.18e-10 → 4.51e-10 → 3.90e-10**（n=1k…200k）→
**4.10e-10**（n=290k）；3 slots 1.20e-8 → … → **1.24e-9**（≈3×1 slot 值）。
随 n 增大**单调收敛到常数**是「存在二次项」的特征指纹。

## 3. 模型分解（这才是判据的量化形式）：t = a·n² + b·n

拟合方式：标准化 + 一维网格搜索比值（避免法方程病态），拟合点 n ∈ {5k, 20k, 50k, 200k}。

| 系列 | a（s/bar²） | b（s/bar） | R² | 对比 `t=c·n` 的 R² |
|---|---|---|---|---|
| dual_ma, 1 slot | **3.7045e-10** | **3.8327e-06** | **0.999998** | 0.947945 |
| dual_ma, 3 slots | **1.1242e-09** | **1.1237e-05** | **0.999998** | 0.947779 |

- 3 slots 的 (a, b) = 1 slot 的 **3.03× / 2.93×** ⇒ slots 维度**线性放大**（每 slot 一份同样的复制与上下文）——
  与 ADR §2.2「每 slot × 每 bar 复制整段历史」逐字吻合。
- 二次项占比：n=1k 8.8% → 5k 32.6% → **15k（93 天）59.2%** → 20k 65.9% → 50k 82.9% →
  **200k 95.1%** → 290k 96.6%（1 slot 同构）。
- **线性项/二次项交叉点** `n* = b/a ≈ 10,350 bar`（1 slot）/ **9,996 bar**（3 slots）≈ **42 个交易日 ≈ 2 个月 M1**。
- 渐近等效复制带宽 = 24 B/bar² ÷ a ≈ **64.8 GB/s**（1 slot）/ **21.3 GB/s**（3 slots，共享内存带宽后摊薄）。
  即二次项**不是 CPU 算力问题，而是纯内存带宽/页回收问题**（与 ADR §2.2「分配器抖动」一致）。

- **复制量（体积）口径：完全支持 ADR §2.2** —— 实测分配字节与大 n 处**吻合到 4 位有效数字（比值 1.0001）**，
  且 `alloc_count ≈ 21.1/bar`（1 slot）/ `57.1/bar`（3 slots）—— 差值 = **18 次/slot/bar**（其中 1 次是那段
  `bars[..=index].to_vec()` 整段复制，另 17 次是 QuickJS 上下文对象：`build_ctx_object` 每 bar 新建
  bar/indicators(7 个闭包)/position/log 等对象）。分配**字节**差值 = 2×960.14 GB（2 个额外 slot），与复制量逐位吻合。
- **时长口径：不支持 ADR §2.2/§2.3 的时长估计**：
  1. M1×5 年实测 **34 s（1 slot）/ 105 s（3 slot）**，而非 ADR 所述「小时级」；原因是现代 DDR5 复制带宽
     实测 ≈65 GB/s（§3），2 TB 只需 ~31 s。
  2. ADR §2.3 的「引擎吞吐 M15 1,620–1,680 bars/s；D1 ≈1,000 bars/s」**本轮未复现**：本轮实测
     小 n 段吞吐 96k–250k bars/s、200k 段 12.8k bars/s，每 bar 固定成本 **b ≈ 3.8 µs/bar**（≈ 260k bars/s 上界），
     与 1,620 bars/s 相差 **~150×**。合理解释（**属推测，需架构师确认，tester 不在此下根因结论**）：
     ADR §2.3 数字来自生产 run 的 `finished_at − started_at`，其中包含 per_bar 全量 jsonb 落库、
     WebSocket 进度帧、`spawn_blocking` 调度与更重插件（macd/kdj 类）；而本轮是**纯引擎 + 冻结输入**。
     ⇒ **两条口径不可直接互比**；本页所有数字均应标注为「引擎内核口径」。
- **时间 vs 内存的真实约束（重要）**：改造前 **峰值 RSS 与 n 近乎无关**（22 MB → 115 MB，200k/290k 段）；
  复制是**瞬时**分配/释放，不驻留。⇒ 改造前长区间的真实约束是 **CPU 时间（二次项）**，**不是内存**。

## 5. 必答问题：**93 天（≈15,000 bar M1）在实测曲线上对应哪个位置，真实约束是时间还是内存？**

- **位置**：15,000 bar ≈ M1 × 93 天（240 bar/交易日 × 63 交易日；ADR §2.2 口径 15,000 bar）落在
  **5k（0.024 s）与 20k（0.207 s）两点之间**，实测 **0.127 s（1 slot）/ 0.382 s（3 slots）**，
  分配量 **5.41 GB / 16.23 GB**，峰值 RSS **23 MB**。
- **曲线上它是「膝点」附近**：交叉点 `n* = b/a ≈ 10,000 bar ≈ 42 交易日 ≈ 2 个月`，
  即 93 天处二次项已占 **59%**、线性项占 41%（n=20k 时 66%）。**「分钟级 ≤3 个月」确实落在
  Σi 二次项刚超过线性项的膝部** ⇒ 支持 ADR §2.2「93 天是 Σi 经验拐点被误写成产品规则」的定性结论。
- **真实约束是时间，不是内存**：
  - 93 天单跑本身 **0.13–0.38 s**，任何一类资源都不是瓶颈；
  - 约束在**区间长度上的斜率**：n 每翻 1 倍，时间 ×3.7（≈2²），内存几乎不变；
  - 93 天之后的代价全部是 CPU/内存带宽（二次项），内存驻留与 n 解耦（29 万 bar 也只 115 MB）。
  ⇒ 现护栏（93 天 / 5 年）在**今日机器上**既非内存护栏、也非「防卡死」护栏（5 年 1 slot 仅 34 s）；
  它拦的是**二次项随区间增长的速率**（且 3 slots 时 5 年 105 s、若插件更重会更高）。

## 8. 已知限制（本轮实测口径的边界）

1. **slots=3 用同一插件**：只量出 slots 维度的线性放大；macd/kdj（插件内自持 O(index) 重算，ADR §2.2 锚点 4）
   的额外二次项**未纳入本轮矩阵**。若 P2 后需要「最坏情况」曲线，应补 `{dual_ma,macd,kdj}` 组合点。
2. **计时粒度**：`wall_ms` 为整数毫秒 ⇒ n ≤ 5k 的点相对误差最高 ±25%；1k 点仅作趋势参考（已在 §1 标注）。
3. **同机负载**：测量期间机器还有其它进程（DB/服务），200k/290k 的 1 slot 点 spread ≈9%；已用 3 次中位缓解，
   但绝对值可能有 ±10% 环境偏差。所有点在 600 s 时限内完成，无 timeout。
4. **单标的**：全部为 `510880` 单标的连续 M1 后缀；跨标的拼接场景未测（本轮不需要）。
5. **引擎内核口径**：不含 per_bar jsonb 落库、WebSocket 进度、`spawn_blocking` 调度与护栏校验
   ⇒ 与 ADR §2.3 的「生产 run 端到端吞吐」**不可直接互比**（见 §4）。

**P2 后的判据对照**：`analyze.py raw_post.txt` 的 **大 n 渐近 slope 应落在 0.9–1.1**（03-test-plan §2.2），
且 200k/290k 点的 `alloc_bytes` 应塌缩为 O(n)（与 bar 数线性，不再随 n² 增长 —— 这是「共享缓冲」生效的
最直接指纹）；峰值 RSS 会**上升**（单一增长式缓冲常驻 = n×48 B/run：290k ≈ 14 MB），这是 D7 已接受的代价。
