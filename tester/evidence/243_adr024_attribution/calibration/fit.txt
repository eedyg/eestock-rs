== 结论式（D1 过渡期用；**P2 改造后必须重标定**）==
   全样本：dur ≈ 1.021s + 16.58 µs/bar × bars    （R²=0.0007，rmse=0.449s）
   含 slots：dur ≈ 0.954s + 58.57 µs/(bar·slot) × bars × slots （R²=0.0209）
   注：本口径**仅适用于过渡期（P2 前）**；P2/P3 改变引擎与写库路径后必须重标定。

== 判别性检验：dur 是否由「进度节流写库次数 min(1001, bars)」主导？ ==
   口径：PROGRESS_THROTTLE_MILLI=1000 时发出的进度帧数 ≈
         bars                    若 bars ≤ 1000
         1001                    若 bars > 1000（0.1% 粒度 ⇒ 恰好 1001 步，与 n 无关）
   模型：dur ≈ c0 + c1×min(1001,bars)
        c0=-91.07 ms  c1=1.226 ms/帧  R²=0.2773  rmse=381.6 ms
   对照（模型 A：dur ~ bars）：R²=0.0007 rmse=448.7 ms
   分档核对（实测中位 dur  vs  c1×min(1001,bars) 预测）：
     bars<=120        N=  6 bars_median=    74 预测=  90.1 ms 实测中位=  74.5 ms
     500<bars<=800    N= 24 bars_median=   598 预测= 733.1 ms 实测中位= 549.1 ms
     900<bars<=1001   N=157 bars_median=   999 预测=1224.7 ms 实测中位= 855.3 ms
     bars>1001        N=174 bars_median=  1330 预测=1227.2 ms 实测中位= 866.3 ms
   ⇒ 结论：生产端到端时长与「进度帧数」近似成正比，而**与 bars 几乎无关**（R² 从 0.0007 升到上值）。
   ⇒ 这直接解释了真路径 bars/s 是伪指标（bars/s ≈ bars/(固定写库成本) ⇒ 随 n 单调上升、随 run 规模无关）。
