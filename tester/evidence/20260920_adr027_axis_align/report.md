## 1. 测量口径（为什么这样量）

| 项 | 口径 | 说明 |
|---|---|---|
| K 线 x | `chart.convertToPixel({timestamp}, {paneId:'candle_pane'}).x` + K 线容器 `rect.left` | **真身**读回（klinecharts `dataIndexToCoordinate`）；canvas 无 DOM 可测 ⇒ 只能向引擎问像素 |
| 曲线 x | 已渲染 `<polyline points>`（user units）+ `svg.getScreenCTM()` → 屏幕像素 | **不重算**映射公式；ts 由渲染 x 反解（`W=1000 / PAD=8`，反解端点由首末顶点 userX 自证 8 → 992） |
| 主判据 Δ984 | `(pK − pC) × 984`；pK/pC = 同一 ts 在**两图共同覆盖 ts 区间**内的归一化位置 | 两图容器宽/内缩不同（K 666px 无内缩；SVG 658px + 4px padding + PAD 8 单位）⇒ 只有归一化才回答「时间轴是否相同」；984 = 曲线 plot 宽度 user units，用于与既有数据级证据的 984 口径对齐 |
| 次要口径 Δraw | `xK − xC`（原始屏幕像素） | 肉眼口径；含容器内缩造成的**常量**偏移（实测锚点处 −9.3 ~ −17.3 px），扣掉该常量才是时间轴扭曲量 |
| 数值模型 | 同一 ts 上「索引线性位置 pI」与「ts 线性位置 pT」之差 × 984 | **非渲染**，纯数据推导（bar 索引 / ts 全量），用于交叉验证假设 |
| 判据 | `max|Δ984| > 2px` ⇒ 不对齐 | 由本波任务给定 |

**测量有效性反证（每条在执行时断言，非事后说明）**

1. **每 bar 一槽**：各态 K 线相邻 bar 的像素间隔只取 `{floor(barSpace), ceil(barSpace)}`（实测 init `[6]`、全览 `[1]`、120 根 `[5]`、300 根 `[1,2]`（barSpace 1.937）、600 根 `[1,2]`（1.029）、对照 `[16,17]`（16.33））⇒ 像素位置只随 **bar 索引**变化、与 ts 间隔无关（缺口被折叠）。
2. **顶点数 = 数据点数**：6 态中 5 态「渲染顶点数 = `/curve` 返回点数」（如 120 根 122 = 122）；唯一不等的是**全览**态（89 vs 1949）——该不等本身是 §4.1 的观测证据，不是方法误差。
3. **双口径互证**：反解口径（与顶点数无关）与「顶点↔ts 逐点配对」口径的最大偏差一致（350.2/350.2、283.3/283.3、340.6/340.7、169.3/169.3、0/0）。

## 3. 交叉验证：假设被证实 / 被修正

### 3.1 「每 bar 一槽（K 线） vs ts 线性（曲线）」= 实测偏差

| 状态 | 实测 max|Δ984|（渲染） | 缺口折叠模型 max|Δ984|（纯数值） | 差 |
|---|---|---|---|
| 初始 kline 窗口 | 350.2 | 345.1 | 5.1 |
| 全览 | 不可测 | 47.5（全窗口 1949 根假设，**数值**） | — |
| 120 根（L2 跳转） | 283.3 | 283.2 | 0.1 |
| 300 根（滚轮缩小） | 340.6 | 341.9 | 1.3 |
| 600 根（滚轮缩小） | 169.3 | 167.5 | 1.8 |
| 对照组：无缺口窗（滚轮放大） | 0.0 | 0.0 | 0.0 |

模型与渲染实测在**每一态**吻合（差 ≤1.8px；对照组同为 0），且取到最大值的 ts 相同 ⇒ 「K 线按 bar 索引等距、曲线按 ts 线性」这一映射口径差异就是偏差的全部来源，量级与位置均可复算。

### 3.2 「窗口越窄偏差越大」——被**修正**（非普适单调）

| 状态 | 共同覆盖区间 ts 跨度 | 区间内最大缺口 | 缺口 ÷ 跨度 | 实测 max|Δ984| |
|---|---|---|---|---|
| 初始 kline 窗口 | 102895s | 66600s | 64.7% | 350.2 |
| 全览 | 4080480s（窗口 = run 全区间） | 239400s（周末） | 5.9%（数值） | 不可测（模型 47.5） |
| 120 根（L2 跳转） | 179108s | 66600s | 37.2% | 283.3 |
| 300 根（滚轮缩小） | 531575s | 239400s | 45.0% | 340.6 |
| 600 根（滚轮缩小） | 791078s | 239400s | 30.3% | 169.3 |
| 对照组：无缺口窗（滚轮放大） | 300s | 300s | 100.0% | 0.0（该态仅 2 根 bar：唯一间隔即 300s，比例退化，不代表"大缺口"） |

读法：**偏差不是窗口宽度的单调函数**（300 根窗 340.6 > 120 根窗 283.3 > 600 根窗 169.3；初始 89~103 根窗 350.2）。真正决定量级的是「窗口内最大缺口时间 ÷ 窗口 ts 跨度」：比例越大，曲线把缺口"摊"到 x 轴的宽度越大，而 K 线把缺口折成 0。**不含大缺口的窗口偏差为 0**（对照组 Δ984 实测 0.0 px，缺口普查仅 `{"300": 2}`）。

### 3.3 缺口签名：偏差在缺口处**阶跃**（方向证据）

以 120 根窗（L2 跳转 `rt_seq=47` 的成交）为例，同一 Δ984 序列在隔夜缺口两侧：

| 缺口之前 | 2026-09-16 06:55:08Z | 68.2 |
| 缺口之前 | 2026-09-16 06:59:59Z | 74.5 |
| **缺口之后** | 2026-09-17 01:30:00Z | -283.3 |
| **缺口之后** | 2026-09-17 01:34:52Z | -277.0 |
| **缺口之后** | 2026-09-17 01:40:02Z | -270.3 |
| **缺口之后** | 2026-09-17 01:44:53Z | -264.0 |

2026-09-17 01:30:00 之前的 66600s 隔夜缺口，把 Δ984 从 **+74.5 px 直接阶跃到 −283.3 px**（一次跳变 358px）；300 根窗同理在**周末缺口**（239400s）处从 +98.0 px 阶跃到 −340.3 px。该阶跃只能由「曲线为缺口分配横轴宽度、K 线不分配」解释。

## 4. 测量中同时抓到、但**不属于**缺口折叠口径的观测量（原样交出，未做原因分析）

### 4.1 全览态：曲线的**渲染数据**未随窗口复位

- 共享窗口 = run 全区间 `2026-08-01 01:30:00Z → 2026-09-17 06:58:00Z`（1949 根）；`/curve?kind=per_bar&k=2000`（无窗口参数）实测返回 **1949 点**。
- 但页面**实际渲染**的聚合曲线与各策略评分曲线 polyline **只有 89 个顶点**，其渲染位置仅占 plot 宽度 **2.5%**（首末顶点 userX = 967.1 → 992），反解 ts 区间 = `2026-09-16 02:17:03Z → 2026-09-17 06:58:00Z`（约 1.2 天）。
- 该态下曲线只画 run 末尾约 1.2 天，K 线画 run 中段 614 根（`2026-08-26 06:25:00Z → 2026-09-14 01:55:00Z`）⇒ **两图 ts 区间不相交**，同 ts 对齐不可测。
- 观测汇总：`渲染顶点 89 ≠ /curve 1949`、`曲线覆盖 plot 宽度 2.5%`、`overlap = ∅`、`曲线头部缺量 959.1 px@984`。**原因分析交回上层**（本角色不做失败归因）。

### 4.2 K 线可见区间 ≠ 共享窗口（6 态中 5 态）

| 状态 | 共享窗口 ts 跨度 | K 线可见 ts 跨度 | 可见 ÷ 窗口 | 窗口左端未覆盖 | 窗口右端未覆盖 |
|---|---|---|---|---|---|
| 初始 kline 窗口 | 103200s | 173400s | **1.680×** | 0s | 0s |
| 全览 | 4080480s | 1625400s | **0.398×** | 2177700s | 277380s |
| 120 根（L2 跳转） | 179400s | 179400s | **1.000×** | 0s | 0s |
| 300 根（滚轮缩小） | 531900s | 696000s | **1.309×** | 0s | 0s |
| 600 根（滚轮缩小） | 791400s | 1314300s | **1.661×** | 0s | 0s |
| 对照组：无缺口窗（滚轮放大） | 600s | 16200s | **27.000×** | 0s | 0s |

只有跳转态（120 根）的 `可见 ÷ 窗口 = 1.000`（页面窗口由跳转真身回执写入，二者同源）。其余态两图**显示的时间范围本身就不同**：300 根态窗口停在 229 根、K 线当前可见 317 根；对照组窗口 3 根而 K 线可见 38 根（27×）。

### 4.3 曲线右端**铺不到窗口右缘**（固定 1 根）

窗口末端 ts（如 `2026-09-17 07:00:00`）落在 K 线 feed 的 buffer bar 上，而 `/curve` 末点恒为 run 最后一根 per_bar（`2026-09-17 06:55:00`）⇒ 曲线末顶点 userX = 989.1~991.6（期望 992），缺 **0.4 ~ 2.9 px@984**。窄窗下该固定 1 根的缺量按 1/N 放大（若窗口仅 10 根 ⇒ 约 98px@984），是随窗口宽度变化的潜在错位源。

### 4.4 K 线渲染上限（影响「全览」的定义）

- 实测 `dataLen = 1000`（feed 单页），run 1949 根；`barSpaceLimit.min = 1`，窗宽 666px ⇒ 最多同时显示约 614 根。
- 因此「全览」在 K 线上**物理上无法**呈现 run 全区间（实测 614/1949 = 31.5%）。任何以「全览」为基准的时间轴对齐断言，都需先解决「K 线此刻显示的到底是哪一段」。

## 5. 结论

1. **曲线与 K 线当前时间轴不对齐**（量化：120 根窗 max|Δ984| = 283.3 px、300 根窗 340.6 px；判据 2px）。
2. **机制被证实**：K 线按 **bar 索引**等距（缺口折叠；引擎 `dataIndexToCoordinate` + 实测相邻间隔恒 = barSpace），曲线按 **ts 线性**（`mapLineByTs`，定义域 = 共享窗口 `data-x-domain`）。实测与模型逐态吻合（≤1.8px）、在缺口处阶跃、无缺口对照组为 0。
3. **推论被修正**：「窗口越窄偏差越大」不普适；驱动量是「窗口内最大缺口 ÷ 窗口 ts 跨度」（600 根窗 169px < 300 根窗 341px）。
4. **全览态不可比**：曲线渲染数据（89 点）与共享窗口（1949 根）不一致，且与 K 线可见区间不相交（§4.1），并叠加 §4.2/§4.4 的窗口级不一致 ⇒ 该态不能作为「对齐」判据，须先修数据/窗口一致性。

## 8. 限制与残余风险

1. **视口宽度受限**：测试视口 1280×720、工作台左栏占约 600px ⇒ K 线 666px、曲线 SVG 658px。绝对量级随窗口宽度变化；结论（是否对齐、机制、方向、阶跃位置）与宽度无关。
2. **曲线 ts 反解依赖 `W=1000 / PAD=8`**：源码与部署 bundle 双向确认（bundle 内 `bd=1e3, Lm=160, Aa=8`），并在每态以「首末顶点 userX = 8 / 992」自证（个别态因数据少 1 根而为 989~992）。
3. **300/600 根态是滚轮手势态**：其共享窗口与 K 线可见区间不一致（§4.2），故偏差在「两图共同覆盖 ts 区间」上归一化后计算；若上层要「窗口 == 可见」的干净对照，需先修窗口一致性。
4. **对照组窗口偏窄**：放大到 ≤40 根时窗口仅覆盖 2 根 bar（ts 跨度 600s）⇒ 对照点仅 3 个采样；「无缺口 ⇒ Δ = 0」在小样本上成立，但不足以刻画「小窗口 + 小缺口」的连续过渡。
5. **未测**：D1 / 其它标的 / 多周期栈内同类图（本次只测 M5 单图）；周末缺口（239400s）仅在 300/600 根态被覆盖到。
